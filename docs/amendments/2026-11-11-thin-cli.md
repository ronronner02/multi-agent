# Thin CLI command boundary

U11 runs on the U22 branch so a clean build no longer depends on daemon modules that U22 deleted.

- Register only `team create|start|chat|approve|merge|result|diff`, `daemon start|stop|status`, and `github status|sign-in`. Use `approve` as the public plan-approval spelling. Removed commands use the normal unknown-command error.
- Keep local process management for daemon start and stop. Let the daemon initialize its own workspace; the CLI only creates the directory needed for its startup log and state. Do not restore deleted daemon exports.
- Use the existing HTTP client and health readiness probe for every other command. Owner commands suppress seat-origin discovery so inherited worker environment variables cannot cause a local database read. Endpoint discovery and owner credentials remain transport configuration.
- Leave terminal and seat command implementations unregistered for U20. Move their shared dependency type to a type-only module instead of keeping the deleted status command.
- Keep direct service, transport, and terminal tests when a mixed test file also covered a deleted command. Remove only assertions and cases belonging to the deleted CLI surface.
- Keep the current package and binary names until the rename unit. Native Windows verification and the Windows CI job update remain with the orchestrator as requested.

The orchestrator approved `POST /api/team-control/github/login/stop` on 2026-11-11. It uses the neighbouring owner-session and anti-forgery guards, calls the existing `GithubCli.stop()`, and returns the current login state with the protocol envelope. It is idempotent while idle and preserves stored credentials. The CLI handles SIGINT during login start, polling requests, and polling waits, sends this stop request once, and exits non-zero with a one-line cancellation message (or the existing JSON error envelope). If the stop request fails, the message says that stopping the daemon login could not be confirmed. Logout is never used for cancellation.
