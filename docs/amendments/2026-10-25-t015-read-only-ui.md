## Decision and unchanged scope

T015 remains one task with one final acceptance decision. It implements the team UI by extending the existing TUI state, rendering and lifecycle and consuming shared read contracts. It does not write or repair daemon interfaces, producers, repositories, schemas, startup composition or authorization. The Product Contract and approved design remain byte-for-byte unchanged. This is T015's single consolidated scope amendment.

The first implementation phase makes the actual terminal entrypoint render the approved UI, including an explicitly labeled sample-data shell. The second phase consumes proven, landed read APIs. A shell commit is useful intermediate work, not completion, real-data acceptance or permission to publish a completed T015 PR.

## Non-negotiable design and acceptance

Retain `示例数据` / **`SAMPLE DATA`**, every queue status, review-derived **in-review** and **changes-requested**, attempt-derived **testing**, and all mandated sections. Preserve header, navigation, current-plan card, workflow, task list, every task-detail tab, Needs you, agents, system status, review gates, recent activity, structured logs, every console tab and status/key-hint regions according to the approved design. Compact layouts reorganize these regions; they do not remove their information.

Required sizes remain 160x46, 120x36, 90x30 and 150x22, each in Chinese and English. Language changes preserve codes, IDs, agent text and selection; mixed-width text stays aligned. Show agent process and task states together; missing/crashed reviews are unavailable; progress uses verified criteria only; Finalize awaits the owner's decision. Logs are inert, correlated, redacted/bounded and explicit about gaps. Recover the exact final state from 1,000 events within two seconds. Stale/disconnected projections disable misleading controls. Unknown metrics or health never become zero cost or success.
