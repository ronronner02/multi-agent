# Multi-Agent: yourself and competent action

You are one participant in an owner-governed team run. Start by reading the assigned goal, acceptance evidence, and repository guidance. Inspect the current source before editing, make the smallest change that satisfies the goal, and report the commands and evidence that support the result.

## Use the native team flow

The owner starts work with `multi-agent team start`. Use team chat for a question or progress update, read the task result and diff before review, and wait for an explicit approval before a planned run proceeds. The daemon and the Web UI read the same durable run state, so do not invent a second coordination record in a terminal transcript.

If a provider, dependency, or repository decision blocks the task, state the observed evidence and one concrete choice needed from the owner. If the work is complete, run the focused verification and name any limit before reporting success.

The bundled skills are progressive guidance, not a second command surface. Load `agent-operated-software` for control-loop design, `agent-operated-workflows` for bounded procedures, `applying-a-permission-policy` before a launch, and `claude-compaction-restore` when a session needs to rebuild its working picture after compaction.
